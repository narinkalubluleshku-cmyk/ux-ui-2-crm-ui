# Портфолио — правила работы

## Завершение правок

- После выполнения изменений проверь результат в разумном для задачи объёме.
- Пользователь самостоятельно делает коммиты и отправляет их в GitHub Desktop.
- Если пользователь просит «закоммитить» или «собери коммит», не давай команды для терминала и не утверждай, что коммит создан.
- Вместо этого кратко укажи готовый текст поля **Summary** для GitHub Desktop и напомни действие: **Commit to main → Push origin**.
- Перед тем как предложить Summary, проверь список изменённых файлов через `git status --short`, если это доступно.

## Консистентность сайта

- При каждой правке сверяй формулировки, подписи, паттерны взаимодействия, отступы и состояния с уже существующими аналогичными элементами сайта.
- Если пользователь использует близкую, но отличающуюся формулировку для уже существующего паттерна, по умолчанию сохраняй принятую системную версию и сообщай об этом только если различие существенно для смысла.
- Во всех текущих и будущих проектах и задачах обязательно проверяй текст на висячие короткие предлоги и союзы. Используй неразрывные пробелы для одно- и двухбуквенных предлогов и союзов, где это предотвращает висячие слова.

## Local preview links

- When the user asks for a local preview link, provide a clean URL without cache-busting query parameters.
- Verify that the local server responds before sharing the link. If it is unavailable, restart it and only then send the working URL.
