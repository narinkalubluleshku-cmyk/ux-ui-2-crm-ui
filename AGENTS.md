# Портфолио — правила работы

## Завершение правок

- После выполнения изменений проверь результат в разумном для задачи объёме.
- Пользователь самостоятельно делает коммиты и отправляет их в GitHub Desktop.
- Если пользователь просит «закоммитить» или «собери коммит», не давай команды для терминала и не утверждай, что коммит создан.
- Вместо этого кратко укажи готовый текст поля **Summary** для GitHub Desktop и напомни действие: **Commit to main → Push origin**.
- Перед тем как предложить Summary, проверь список изменённых файлов через `git status --short`, если это доступно.

## Консистентность сайта

- При каждой правке сверяй формулировки, подписи, паттерны взаимодействия, отступы и состояния с уже существующими аналогичными элементами сайта.
- Если пользователь использует близкую, но отличающуюся формулировку для уже существующего паттерна, по умолчанию сохраняй принятую системную версию и сообщай об этом только если различие существенно для смысла.
- Во всех текущих и будущих проектах и задачах обязательно проверяй текст на висячие короткие предлоги и союзы. Используй неразрывные пробелы для одно- и двухбуквенных предлогов и союзов, где это предотвращает висячие слова.
- После любых предлогов всегда ставь неразрывный пробел, независимо от их длины. В HTML используй `&nbsp;`, в обычном тексте — символ U+00A0. Применяй это правило ко всем новым и редактируемым текстам сайта; также сохраняй неразрывные пробелы после коротких союзов.

## Система типографики и отступов

- Применяй эти принципы ко всем проектам: с начала работы задавай единую систему шрифтов и отступов, а в существующих проектах используй и развивай принятую систему.
- Храни семейства шрифтов, размеры, начертания, межстрочные интервалы и шкалу отступов в общих токенах (например, CSS-переменных). Для одинаковых по назначению элементов используй общие стили и семантические токены, чтобы изменение одного значения применялось ко всем аналогичным местам.
- Собирай связанные элементы по принципу Auto Layout в Figma: используй нормальный поток, Flexbox или Grid, автоматические размеры по содержимому и явные промежутки через gap. Не имитируй расстояния фиксированной высотой контейнера, пустыми блоками или абсолютными координатами.
- При изменении размера объекта или шрифта соседние элементы должны автоматически перемещаться вместе с содержимым, сохраняя согласованный промежуток между фактическими границами блоков. Уменьшение заголовка не должно оставлять текст или обложку на прежней позиции с пустотой между ними.
- Если необходимо осознанно изменить сам промежуток, меняй соответствующий общий токен или стиль компонента, а не отдельный экземпляр. Отдельные исключения допускаются только при реальном отличии назначения элемента.
- При удалении элемента удаляй также зарезервированное под него место и связанные отступы.
- После изменения размеров, шрифтов или состава блока проверяй связанные отступы и все аналогичные компоненты одновременно на десктопе и мобильных. Учитывай переносы строк, длинный текст и отсутствие необязательных элементов.

## Local preview links

- When the user asks for a local preview link, provide a clean URL without cache-busting query parameters.
- Verify that the local server responds before sharing the link. If it is unavailable, restart it and only then send the working URL.
